# Mobile API handoff: token billing

This is a breaking cutover from subscriptions to organization-owned token billing. Remove active plan discovery and active-subscription/entitlement flows; there is no subscription purchase fallback. Read `GET /api/tokens` for the authenticated employer organization's token settings, balance, and ledger, and create manual purchases with `token_quantity` rather than a plan identifier. A purchase snapshots the integer token quantity, rupiah conversion rate, and total price. Orders have no automatic payment deadline: retain the quoted rate until cancellation or any explicitly assigned deadline. Uploading proof only moves the order to verification; tokens are credited only after administrator approval. Support pending-order conflicts, cancellation while pending, and rejected-proof resubmission.

Tokens do not expire. Only job-vacancy and training publication consumes tokens; drafts and non-publication features remain free and require no subscription or token charge. Existing subscription and payment history remains historical, but no subscription entitlement is activated after cutover.

Publication is immediate on successful publish, not queued for review. Replace submit workflows and `/submit` calls with publish workflows and `/publish`; display publication timestamps, expiry, token cost/cycle, and current-publication state. Active publications cannot be edited. Closing or expiry does not refund tokens, and public detail links remain readable as archives after publication ends. Republish manually after closure/expiry at the then-current full token price; no extension is available while active. Training cannot be republished once its event has started, completed, or been cancelled. Existing applicants/participants remain associated with the same posting.
